# UI Audit 001

Scope: home hero at laptop and desktop widths.

## Findings

1. **HIGH, R-03, R-35**: `src/pages/home/Hero.tsx:66` switches the map to `position: absolute` at `md` (768px) and gives it `w-[64vw]`, while `src/pages/home/Hero.tsx:43` lets the headline grow to `8.4vw` with no reserved map column. Absolute content has no layout space, so map and headline share the same canvas. At the attached 1567px viewport, headline resolves to about 128px and the map to about 1003px. Their boxes overlap by design. Fix: use a real two-column hero state only when both headline and map fit, otherwise keep map in document flow.

2. **MEDIUM, R-03, R-35**: Hero has two responsive states only. Below `md`, map flows under copy. At `md` and above, map is absolute. No middle state exists for tablet and laptop widths, where both elements need to coexist. Fix: add a content-driven breakpoint for a two-column layout, then use the desktop map placement only above that point.

3. **LOW, R-31**: `min-h-[100svh]` plus `bottom-[9vh]` assumes one viewport height. Header, headline, CTA, map, and caption have no shared vertical layout contract. On shorter laptops, map can cover body copy even after horizontal overlap is fixed. Fix: use grid rows or safe vertical placement with map top/bottom bounds derived from hero content.
